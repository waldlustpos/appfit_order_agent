계산 정본은 `appfit-fleet/SCALING.md`(간격별 표·재계산 공식·시나리오별 코드 수정 범위). 여기엔 판단에 필요한 결론만.

**무료 천장은 하루 heartbeat 100,000회.** Workers 요청과 D1 쓰기 한도가 둘 다 100,000/일이고 heartbeat 1회가 둘을 동시에 1씩 쓴다. 수용 대수(15% 여유 반영): 60초 59대 · 3분 177대 · 10분 590대 · 40분 2,360대.

**무료의 진짜 벽은 heartbeat 가 아니라 대시보드다.** `/api/devices` 가 2N rows read 를 쓰는데, 2000대 × 15초 폴링이면 하루 768만 행으로 500만 한도를 넘는다. 요청당 CPU 10ms 도 2000행 JSON 직렬화에 위험하다. **무료 2000대는 대시보드를 페이지네이션으로 다시 짜야 성립한다.**

**비용 절벽이 60초와 2분 사이에 있다.** D1 쓰기($1.00/M)가 Workers 요청($0.30/M)보다 3.3배 비싸다. 2000대 60초는 월 8,640만 쓰기로 포함량 5,000만을 넘어 **$67/월**이지만, 2분으로 늘리면 포함량 안에 들어가 **$16/월**이 된다. 10분이면 세 자원 전부 포함량 안이라 **기본요금 $5**뿐이다.

유료로 가면 요청당 CPU 가 10ms → 30초로 풀려서 무료의 read·CPU 제약이 함께 사라진다. 페이지네이션이 필수에서 선택으로 바뀐다.

**결론: 2000대는 유료 $5(10분)가 기본, 반응성 필요하면 $16(2분).** 무료를 짜내는 비용이 훨씬 크다.

**미리 해둘 것:** `fleet_reporter.dart` 의 `maxIntervalSeconds = 600` 은 클라이언트측 상한이라, 10분을 넘겨야 하는 시점에 **매장의 전 기기 앱 업데이트**가 필요하다. 3600 으로 미리 올려두면 동작은 그대로면서 이후 조절이 서버 상수 한 줄로 끝난다. **기기가 매장에 나가기 전에 결정할 것.**
