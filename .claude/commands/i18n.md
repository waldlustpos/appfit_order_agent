description: i18n JSON 변경분을 키 구조 변경일 때만 l10n-auditor로 감사 후 strings.g.dart 재생성
---

> 이 프로젝트의 slang 은 **standalone** 설정(`slang` + `slang_flutter`, `slang_build_runner` 없음)이다.
> 따라서 `strings.g.dart` 는 `build_runner` 가 아니라 **slang CLI** 로만 생성된다.
> 또한 Flutter 프로젝트라 `dart run` 은 SDK 해석 에러가 나므로 **`flutter pub run`** 을 써야 한다.

핵심 원칙: **l10n-auditor 감사(느림, 토큰 큼)는 키 구조가 바뀔 때만 의미가 있다.**
기존 키의 **값(단어)만** 바꾸는 변경은 3로캘 동기화가 깨질 수 없으므로 감사를 건너뛰고 바로 재생성한다.

아래 순서로 실행한다:

1. Bash 툴로 변경된 i18n 파일 확인:
   ```
   git diff --name-only lib/i18n/
   ```
   `*.i18n.json` 변경이 하나도 없으면 "i18n 변경 없음" 으로 종료한다.
   (`strings.g.dart` 만 바뀐 경우는 소스 변경이 아니므로 종료 대상.)

2. **변경 유형 자동 판별** — `*.i18n.json` 의 git diff 에서 추가(`+`)/삭제(`-`)된 줄의 **키 토큰 집합**을 비교한다. 양쪽이 같으면 값만 바뀐 것(`VALUE_ONLY`), 다르면 키가 추가/삭제/이름변경된 것(`STRUCTURAL`):
   ```bash
   diff=$(git diff -U0 -- lib/i18n/*.i18n.json)
   added=$(printf '%s\n' "$diff"   | grep -E '^\+' | grep -vE '^\+\+\+' | grep -oE '"[^"]+"[[:space:]]*:' | sort)
   removed=$(printf '%s\n' "$diff" | grep -E '^-'  | grep -vE '^---'    | grep -oE '"[^"]+"[[:space:]]*:' | sort)
   if [ "$added" = "$removed" ]; then echo VALUE_ONLY; else echo STRUCTURAL; fi
   ```

3. 판별 결과에 따라 분기한다:
   - **VALUE_ONLY**: "값만 변경 — 키 구조 동일, l10n-auditor 감사 생략" 한 줄만 알리고 4단계로 바로 간다.
   - **STRUCTURAL**: **l10n-auditor 서브에이전트를 호출**하여 ko/en/ja 키 누락·중복·미사용을 감사한다. 누락이 발견되면 결과를 사용자에게 먼저 보고하고 진행 여부를 묻는다. (판별이 애매하거나 사용자가 명시적으로 감사를 요청하면 이 경로를 탄다.)

4. 사용자가 진행에 동의하거나 감사가 생략/통과되면 slang 으로 재생성:
   ```
   flutter pub run slang
   ```
   (standalone slang 은 0.1초 내외로 끝난다. `build_runner build` 로는 `strings.g.dart` 가 갱신되지 않으니 쓰지 말 것.)

5. 생성된 `lib/i18n/strings.g.dart` 변경 라인 수와 판별 결과(VALUE_ONLY/STRUCTURAL)를 요약하고 완료를 알린다.
