# 기기 관제(Fleet) 대상 매장 목록

> **⛔ 현재 이 목록은 쓰이지 않는다.** `lib/config/fleet_config.dart` 의
> `FleetConfig.enabled = false` 로 관제가 통째로 꺼져 있어(정식 도입 전),
> 앱이 이 파일을 조회하지 않는다. 대상 매장 정책은 도입 시점에 다시 세운다.
> 아래는 다시 켠 뒤의 절차다.

`fleet_stores.json` 은 **어느 매장이 관제 대상인지**를 정하는 정본이다. 앱은 로그인
시 이 파일을 조회해 자기 매장이 목록에 있을 때만 관제 보고를 시작한다.

관제를 전 함대에 한꺼번에 켤 수는 없다 — 파일럿은 실기기 몇 대로 시작해야 하고,
무료 티어 천장도 heartbeat 하루 10만회(60초 간격 = 59대)다. 목록이 앱 밖에 있으므로
**앱 재배포 없이** 범위를 넓히거나 되돌릴 수 있는 게 이 구조의 요점이다.

레포의 이 파일이 정본이고, 서버 파일은 그 사본이다. **서버에서 직접 고치지 말 것** —
다음 업로드 때 조용히 되돌아간다.

## 형식

```json
{
  "version": 1,
  "stores": ["MHST00001", "TPCP00002"]
}
```

- `stores` 는 **매장 코드 완전일치** 목록이다. 프리픽스 와일드카드(`MHST*`)는 지원하지
  않는다 — 손이 미끄러져 브랜드 전체를 켜는 사고를 구조적으로 막는다.
- 대소문자·앞뒤 공백은 앱이 정규화한다.
- `stores` 를 빈 배열로 두면 **전부 OFF** 다(= 파일럿 중단). 키를 통째로 빼도 같다.
- `version` 은 앞으로의 스키마 변경 대비 표식이며 현재 앱은 읽지 않는다.

## 업로드

배포 스크립트(`deploy_apk.sh` / `deploy_windows.ps1`)는 아티팩트와 version JSON 2개만
다룬다. 이 파일은 **파이프라인 밖의 수동 자산**이다.

```bash
scp -i ~/.ssh/LightsailDefaultKey-ap-northeast-3.pem \
    fleet_targets/fleet_stores.json \
    ec2-user@52.78.172.188:/var/www/docs/waldpay_html/
```

확인:

```bash
curl -s http://waldpay.kokonutstamp2.com/fleet_stores.json
```

## 반영 시점

앱은 **로그인할 때** 목록을 다시 받는다. 목록을 고친 뒤 대상 기기가 재로그인(또는 앱
재시작 → 자동 로그인)해야 반영된다. 즉시 반영이 필요하면 해당 기기를 재시작한다.

조회에 실패하면(오프라인·404·형식 오류) 앱은 **마지막으로 성공한 목록**으로 판정한다.
캐시조차 없는 기기(최초 설치)만 OFF 다. 그래서 매장 인터넷이 잠깐 끊겨도 파일럿 기기가
대시보드에서 사라지지 않는다.

## 주의

- 이 파일은 **평문 HTTP · 무인증 공개 파일**이 된다. 매장 코드는 곧 로그인 ID 이므로
  목록 공개는 계정 열거를 조금 돕는다. 파일럿 범위에서는 수용하기로 한 트레이드오프다.
- 목록에 넣어도 관제가 안 붙으면 **빌드 쪽 설정**부터 의심한다. `.env` 의
  `FLEET_BASE_URL`/`FLEET_DEVICE_KEY` 가 빠진 빌드는 목록과 무관하게 항상 OFF 이고,
  로그에 `(noop)` 만 찍힌다.
