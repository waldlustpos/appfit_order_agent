고객 주문이 AppFit 서버를 거쳐 에이전트에 도착해 주방·프린터·화면까지 반영되는 흐름을 단계별로 본다. 수신·버퍼·가드는 Order Core의 6개 매니저가 담당하고, 출력 단계는 출력 파이프라인 뷰로 이어진다. 실패 지점마다 폴링 안전망과 복구 큐가 받친다.

7
UI 반영
OrderStateManager → 화면
OrderState에 반영되어 주문 카드가 화면에 뜨고, 부수효과로 알림음과 화면 블링크가 울린다. KDS 모드도 동일한 OrderState를 공유하므로 별도 동기화가 없다.
OrderStateManagerSoundServiceBlinkServiceAlertManager
이 흐름의 핵심: 유입이 3경로(WSS · 폴링 · 수동)라도 버퍼→가드→상세조회→상태 변경의 단일 파이프라인으로 합류하고, 중복은 4중 가드가, 유실은 폴링 안전망 + _pendingDetailReprint 복구 큐가 막는다. 출력은 updateOrderStatus await 이후에만 시작되므로 "접수 안 된 주문이 인쇄되는" 역전이 구조적으로 불가능하다.
