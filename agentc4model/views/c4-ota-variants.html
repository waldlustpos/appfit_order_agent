OTA 자가 업데이트 · 빌드 변형
에이전트는 OTA 서버(waldpay.kokonutstamp2.com · Lightsail)에서 스스로 새 버전을 내려받아 교체한다. 하나의 코드베이스가 --dart-define=APPFIT_VARIANT로 update / standalone 두 변형으로 갈라지며, OTA 채널·뮤텍스·임시 폴더가 완전 분리되어 같은 머신에 병존 설치·실행이 가능하다.
빌드 스크립트 -Variant→ ① --dart-define=APPFIT_VARIANT→ AppEnv.isStandalone (const)→ 컴파일 타임 분기 UpdateConfig (Win OTA) OtaConfig (Android OTA) ② APPFIT_WINDOWS_VARIANT env→ CMake 매크로→ main.cpp 뮤텍스·창 제목
플랫폼별 자가 업데이트 흐름
Windows는 앱 시작 시점에 스스로 교체 후 재시작, Android는 APK 다운로드 후 설치 인텐트로 위임한다.
Windows시작 시 자가 교체
release 빌드 한정 — main.dart 부팅 단계에서 실행. 타임아웃: 체크 10s / 다운로드 10m.
1
runStartupUpdateFlow()
runApp 이전, 앱 시작 시점에 업데이트 플로 진입.
2
version JSON 비교
변형별 *_windows_version.json 을 받아 현재 버전과 비교. 최신이면 그대로 부팅.
3
ZIP 다운로드
변형별 *_windows.zip 을 임시 작업 폴더에 내려받아 압축 해제.
4
updater.bat 생성·실행
taskkill 로 실행 중 프로세스 종료 → robocopy 로 새 파일 덮어쓰기.
5
exit(0) → 재시작
앱이 스스로 종료하면 배치가 교체를 마치고 새 exe 를 재실행.
AndroidAPK 다운로드 → 설치 위임
Sunmi 단말 대상 — 교체 자체는 시스템 패키지 설치기가 수행.
1
OtaConfig 채널 확인
변형별 *_version.json 으로 서버 최신 버전 조회.
2
APK 다운로드
변형별 appfit_order_agent[_standalone].apk 를 내려받는다.
3
app_installer 설치
설치 인텐트를 띄워 시스템 설치기로 위임 — 교체·재실행은 앱 코드 외부(시스템/운영자)에서 이뤄진다.
변형 비교 — update vs standalone
채널 파일명·exe명·뮤텍스·임시 폴더가 전부 분리되어 동시 업데이트·동시 실행 충돌이 없다.

⚠ 버전 정본 이원화 — Android와 Windows는 서로 다른 파일을 읽는다

두 플랫폼의 버전 정본은 분리되어 있다. Windows 빌드 스크립트는 pubspec.yaml 을 읽지 않으므로, 한쪽만 올리면 다른 쪽 배포 버전은 그대로다.

Android 정본
pubspec.yaml 의 version: x.y.z+n → build_main.sh / OTA APK 버전.
Windows 정본
version_windows.txt (x.y.z+n) → build_windows.ps1 / deploy_windows.ps1 / build_installer.ps1 이 --build-name / --build-number 로 주입.
